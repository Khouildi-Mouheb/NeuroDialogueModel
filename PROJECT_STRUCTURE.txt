DEPENDENCY FLOW
===============

1. PRESENTATION uses APPLICATION
   presentation/main.py
       ↓
   application/chat_orchestrator.py

2. APPLICATION uses PORTS (not adapters!)
   application/chat_orchestrator.py
       ↓
   ports/llm_port.py
   ports/emotion_port.py
   ports/intent_port.py
   ports/verification_strategy_port.py

3. ADAPTERS implement PORTS
   adapters/generation/cloud_based_generator.py
       ↓ (implements)
   ports/llm_port.py

4. EVERYTHING uses DOMAIN
   domain/entities/user_query.py
   domain/value_objects/user_state.py
   domain/context/generator_context.py
   domain/services/user_state_service.py


ARCHITECTURE RULES (STRICT ENFORCEMENT)
========================================

✅ ALLOWED IMPORTS:

DOMAIN:     Only: Python stdlib
PORTS:      Only: abc, typing
ADAPTERS:   From: domain, ports, external libs
APPLICATION: From: domain, ports
PRESENTATION: From: application, adapters, frameworks

❌ NEVER ALLOWED:

- Domain ← adapters (circular!)
- Domain ← application (circular!)
- Domain ← presentation (circular!)
- Application ← adapters (breaks inversion!)
- Ports ← anything (they're interfaces!)
- Circular imports anywhere


HOW TO ADD NEW FEATURES
========================

🔧 New LLM Provider:
   1. Create: adapters/generation/my_llm.py
   2. Implement: LLMPort interface
   3. Pass to: ChatOrchestrator(llm_port=my_adapter)

🔧 New Verification:
   1. Create: adapters/verification/my_verificator.py
   2. Implement: VerificationPort interface
   3. Add to: verificators list in presentation/main.py

🔧 New Domain Service:
   1. Create: domain/services/my_service.py
   2. Import: Only domain entities/values
   3. Call from: application/chat_orchestrator.py

🔧 New Presentation:
   1. Create: presentation/my_interface.py
   2. Use: ChatOrchestrator from application layer
   3. Create adapters in presentation __init__
